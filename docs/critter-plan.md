# Critter rework: plan and phase log

Goals: (1) mids no longer split into smalls (a big still breaks into 2 mids), (2) walking with more detail, (3) a different attack animation per size.
Decisions (owner approved the defaults): 1a mids don't split; 2a attacks get a short readable wind-up; 3a the big slam hits only the player (1 heart, as now).

## Findings
- Rules live in `src/game/critters.js` (`TIERS`, `Critter.step`, `splits`); the look is `src/hero/critter.js` (`buildFurry` merges every body part into ONE vertex-coloured geometry per tier, so limbs cannot move; the only motion is hop / squash / tilt / flash). `main.js` calls `c.splits()` in `critterDied` and `hurtPlayer(c)` when `step()` returns `'attack'` (instant bite on contact, 0.9 s cooldown).
- Draw calls are the bottleneck (render-bound), so the rework must stay one draw call per critter (skinned mesh with bones, not one mesh per limb).

## Phases
1. Split rule (data only). DONE
2. DONE. Skeleton: one SkinnedMesh per tier (bones: root/hips, body, head, arm L/R, foot L/R), rest pose identical to today, hop moved onto the rig. Golden/screenshots identical at rest.
3. DONE. Walk cycle per size, driven by distance travelled (no foot slide): mini scurry, mid hunched stomp with opposite arm swing and head bob, big lumber with sway, dragging arms and a step thud.
4. DONE. Attack logic: `chase -> windup -> strike -> recover`; damage only on the strike if the player is still in reach; killed or knocked mid wind-up cannot hit. Wind-ups ~0.15 s mini, ~0.3 s mid, ~0.5 s big (RULES-style constants).
5. DONE. Attack animations: mini crouch + lunge-bite, mid rear back + claw swipe, big raise fists + ground slam (dust ring, camera thump).
6. DONE. Full regression, HANDOFF, send build.

## Phase log

- Phase 2: `src/hero/critter.js` now builds each size as ONE `SkinnedMesh` (rigid skinning: each part bound to one bone via `skinIndex`/`skinWeight` baked into the merged geometry) on a 7-bone skeleton `BONE = { root, body, head, armL, armR, footL, footR }` (exported). Hierarchy: root > (body > head, armL, armR), footL, footR. Joint positions come from `buildFurry` (`pivots`), each view makes its own bones (`makeBones`) and `dispose()` frees the skeleton. Rest pose = the old static shape. The hop/squash/tilt still live on the `rig` group, unchanged, so the look is identical; Phase 3 adds bone motion on top (root bone is free for body bob).
  Verified: `tools/critter-lineup.mjs` renders 6 critters (2 per size) deterministically; old vs new build: identical draw calls (225) and triangles (116,972), 1 and 4 differing pixels of 480,000 (max channel diff 1 and 19, silhouette rounding). Posing individual bones in the browser moves exactly the intended parts (eyeballed). New `tests/critter-rig.test.mjs` (5 tests, mutation-checked: swapped arms, face on body, feet on body): bone coverage, left/right sides, rest pose == original shape, one bone moves only its own parts. `npm test` 208/208; game-run, tutorial, e2e-controller, hero-select, aim-and-shot pass. Perf with a 34-critter wave-10 crowd: ~0.28-0.33 ms per frame JS vs 0.27-0.30 before (+0.03 ms); create/render/dispose soak of 300 critters: GPU textures and heap stay flat (no leak).
  Golden: the golden-master's state now drifts from the pre-skeleton recording, but only because three draws 4 `Math.random()` values per object it creates (UUIDs; 7 bones + skeleton + mesh per critter shift the seeded sequence, so spawn positions change). - Phase 3: walk cycle. `src/hero/critterWalk.js` (pure: `WALK` tuning per tier, `phaseAt`, `walkPose`) + the view drives the bones from it. The stride phase advances with the ground the critter REALLY covers (`phase = 2π * distance / stride`; clamped per frame so a shove/teleport cannot spin the legs; a blocked critter stands still), amplitude fades in/out with a smoothed speed so it eases into and out of a walk. One cycle = two steps: feet alternate (lift + forward/back swing, planted foot slides back at ~ground speed), arms swing opposite the same-side foot through a spring (mini stiff, big soft and late), body rolls / twists / leans into the run, head nods each step and sways less than the body, body bounces once per step (mini 0.26, mid 0.14, big 0.07 x radius), heavy feet thump (squash kick: big 1.4, mid 0.6, mini none), idle breathing when still. Tuning lives in `WALK`.
  Tests: `tests/critter-walk.test.mjs` (7, pure maths: rest at m=0, periodic, feet alternate/never both up, arm/foot pairing, bounce twice and sway once per cycle, planted-foot speed within 0.7-1.06 x ground speed, step cadence per tier, heavier = less hop/softer arms/more thud) and 5 more in `tests/critter-rig.test.mjs` through the real view (still = rest, walking alternates and settles, blocked critter does not run on the spot, teleport cannot spin legs, thump on heavy ones only, arms swing >0.25 rad at every size). Mutation-checked (clock-driven stride, no thump, feet lifting together, arms swinging together all fail). Unit tests 220/220.
  Looked at: `tools/critter-sheet.mjs` films each size from a low side camera, 8 frames over one cycle (props hidden); all three read well. Real game camera frame checked. Golden: simulation STATE identical to the post-skeleton recording; only the fight checkpoints' pixels differ (critters animate), everything else identical. New golden baseline for Phases 4-6 = recording after this phase. Perf (34-critter crowd): ~0.29-0.33 ms/frame JS, same as before within noise; leak soak flat.
  Found by the new test and fixed: the mini's arm spring was too soft to follow its ~29 rad/s flap (it reached 0.15 of 0.55 rad), so arm spring stiffness is now tuned per size.
- Phase 4: attack logic in `src/game/critters.js`. New per-size data `TIERS[...].atk = { windup, recover, reach }` (mini 0.15/0.25/0.55, mid 0.3/0.35/0.5, big 0.5/0.45/0.9 s/s/units past touching). `Critter.step` states: `chase -> windup -> recover -> chase`. It starts winding up at 3/4 of its reach and when its cooldown (`ATTACK_COOLDOWN` 0.9 s, counted from the start of a wind-up, so the bite rate is unchanged) allows; it is planted (no walking) while winding up, walks at 30% while recovering, keeps eyes on the player at a slower turn rate while attacking. At the end of the wind-up the strike lands ONLY if the player is within reach right then: `step()` returns `'attack'` (landed: caller hurts the player, critter recoils as before) or `'whiff'` (dodged; Phase 5 uses it for the slam effects); `main.js` still hurts the player only on `'attack'`. A dead critter is out of `step()`'s states so it can never strike; crowd separation now applies to every living critter (windup/recover included). `t`/`actDur` hold time left / total of the current wind-up or recovery for the view. Removed unused `PLAYER_HIT_PAD`.
  Tests: `tests/critter-attack.test.mjs` (10: telegraph before damage, lands at end of wind-up for each size, telegraph grows with size, dodge = whiff, dies mid wind-up = no strike, planted then walks again, recoil only on a hit, attack rate unchanged, no wind-up out of range, separation/alive while attacking, full recovery and cooldown pacing). Mutation-checked: always-hit, walking while winding up, zero telegraph, lost separation, no recovery all fail (two initial survivors led to stronger tests). Unit tests 230/230; game-run, tutorial, e2e-controller, aim-and-shot pass.
  Balance check (node sim, 20 s vs one critter): a standing player takes ~21 bites (mini/mid), 19 (big), same as the old 0.9 s bite rate; a sidestepping player at 3 u/s now dodges mini and mid strikes entirely. So play is a little easier for a moving player (the telegraph), which also helps the "wave 1 too hard" feedback; knobs are `atk.reach` (smaller = easier to dodge) and `windup`.
  Golden: simulation changed on purpose, new baseline recorded after this phase.
- Phase 5: attack animations. `src/hero/critterAttack.js` (pure: per-size WIND and STRIKE poses, `attackPose(tier, state, k)`, `attackWeight`): windup = rest -> WIND (eased), recover = WIND -> STRIKE fast (`snap` share of the time) then STRIKE -> rest. Fields: body lean/twist/roll, head pitch, arm swing and splay, lift, forward lunge (world units, kept <= the strike's reach, tested), squash. Mini: crouch + draw back, then dive jaws-first with arms grabbing (furthest lunge). Furry: rear back, one claw hoisted overhead, then rake it down across the body with a twist and a step in. Giant: rise on toes with BOTH fists overhead (arms tremble), then slam: body drops, squash, biggest jolt. The view blends the pose over the walk (`attackWeight`), planted feet, a spring jolt (`STRIKE_KICK`) at the strike; leftover arm splay is cleared when the state changes. `main.js` `strikeFx(c)` runs on every strike result (`'attack'` or `'whiff'`): giant = ground ring + dust + camera thump (scaled by distance to the player), smaller = a puff of dust. No new sounds (none existed for this; optional follow-up).
  Found and fixed while filming: a critter with `speed` 0 (only my tools do that; the game never does) made the walk code divide by zero -> NaN transforms -> the mesh vanished. Guarded with `Math.max(c.speed, 0.01)` plus a regression test.

Mutation-checked (no lunge/squash, no strike jolt, arm not posed, no splay reset; the splay-reset one survived at first and led to the interrupted-attack test). Unit tests 242/242.
